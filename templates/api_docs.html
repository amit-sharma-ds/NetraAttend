NetraAttend API v1

For punching machines, payroll and HR software. Base URL: {{ base_url }}/api/v1

Authentication

Every request sends an API key in a header. The admin creates keys on the API page of NetraAttend.

X-API-Key: na_xxxxxxxxxxxxxxxx        (or: Authorization: Bearer na_xxxxxxxxxxxxxxxx)
PermissionAllows
readAll GET endpoints
punchPOST /punches (machines sending attendance)

Limit: {{ rate }} requests per minute per key. Use https when calling from outside the office. All times are office local time (IST), format YYYY-MM-DD HH:MM:SS. The employee is always identified by emp_code (the Employee ID) - keep it the same in every system.

Errors

{"ok": false, "error": "Invalid or revoked API key."}

401 missing / wrong key · 403 key lacks the permission · 400 bad input · 404 unknown employee or endpoint · 429 too many requests

GET/employees

Employee list. ?active=true = active only.

curl -H "X-API-Key: KEY" "{{ base_url }}/api/v1/employees?active=true"
{"ok": true, "count": 2, "employees": [
  {"emp_code": "102", "name": "amit", "department": "aiml", "active": true,
   "field_allowed": false, "face_registered": true}, ...]}

GET/attendance

Day-wise attendance with the office rules applied (on time / late / half day / leave / absent) and a per-employee summary.

Parameter
from, toYYYY-MM-DD (default today; max {{ max_days }} days)
emp_codeoptional - one employee
curl -H "X-API-Key: KEY" "{{ base_url }}/api/v1/attendance?from=2026-10-01&to=2026-10-31"
{"ok": true, "from": "2026-10-01", "to": "2026-10-31",
 "days": [{"emp_code": "102", "name": "amit", "department": "aiml", "date": "2026-10-16",
           "in": "10:38", "out": "19:05", "worked_minutes": 507, "status": "On Time",
           "late_minutes": 0, "leave": null, "punches": 3, "source": "camera"}, ...],
 "summary": [{"emp_code": "102", "name": "amit", "present": 20, "on_time": 17, "late": 3,
              "half_day": 0, "leave": 1, "absent": 1, "late_minutes": 64, "worked_minutes": 10140}]}

status is one of: On Time, Late, Half Day, Leave, Absent, Weekly Off, Holiday, Not In Yet. worked_minutes = first IN to last OUT (null when there is no OUT).

GET/punches

Every IN / OUT punch (camera, field app, machines, manual), oldest first - use it to sync incrementally.

Parameter
sincereturn punches after this time (default: start of today)
untiloptional end time
emp_codeoptional
limitdefault 500, max 1000
curl -H "X-API-Key: KEY" "{{ base_url }}/api/v1/punches?since=2026-10-16%2010:00:00"
{"ok": true, "count": 2, "next_since": "2026-10-16 10:44:12", "punches": [
  {"id": "6a1...", "emp_code": "102", "name": "amit", "time": "2026-10-16 10:38:40", "kind": "IN", "source": "camera"},
  {"id": "6a2...", "emp_code": "106", "name": "sahil", "time": "2026-10-16 10:44:12", "kind": "IN", "source": "field",
   "lat": 22.71957, "lng": 75.85773, "accuracy_m": 12, "face_verified": true}]}

Sync loop: call with since = the next_since you got last time.

POST/punches

A machine or system sends punches (needs the punch permission). One punch, or up to {{ max_batch }} in "punches".

Field
emp_coderequired - Employee ID
timeoptional - punch time (default: now). Up to {{ past_days }} days back is accepted.
deviceoptional - machine name, e.g. "gate-1" (default: the key's name)
kindoptional - IN or OUT. Leave it out and the first punch of the day is IN, later punches are OUT.
curl -X POST -H "X-API-Key: KEY" -H "Content-Type: application/json" \
     -d '{"emp_code": "102", "time": "2026-10-16 10:38:00", "device": "gate-1"}' \
     "{{ base_url }}/api/v1/punches"
{"punches": [{"emp_code": "102", "time": "2026-10-16 10:38:00"},
             {"emp_code": "104", "time": "2026-10-16 10:41:30"}]}
{"ok": true, "saved": 2, "duplicates": 0, "failed": 0, "results": [
  {"index": 0, "ok": true, "emp_code": "102", "time": "2026-10-16 10:38:00", "kind": "IN", "result": "saved"}, ...]}

Sending the same punch again is safe - it comes back as "duplicate" and is not counted twice. Old punches that arrive late are put in the right place (earliest punch of the day = IN, latest = OUT). The same late / half-day rules as the camera apply.

{"ok": true, "count": 1, "leaves": [{"id": "6a3...", "emp_code": "102", "name": "amit", "type": "Sick Leave",
  "from": "2026-10-14", "to": "2026-10-14", "half_day": false, "days": 1.0, "status": "approved",
  "reason": "fever", "applied_at": "2026-10-13 20:10:00", "decided_at": "2026-10-14 09:00:00"}]}
